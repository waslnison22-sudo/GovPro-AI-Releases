# Политика обработки данных GovPro AI

> Техническое описание текущей архитектуры обработки данных. Перед публичным Stable-релизом этот документ должен быть дополнен юридическими реквизитами владельца продукта, фактическими сроками хранения и применимым законодательством.

## Какие данные обрабатываются

### Учётная запись

Для публичного входа используется учётная запись Supabase Auth. Приложение получает данные, необходимые для аутентификации и определения текущей сессии.

### Рабочие данные

В зависимости от функций приложения сервер может получать:

- вопросы пользователя;
- данные выбранного Server Profile;
- данные дел;
, включая события и доказательства;
- изображения документов, если пользователь прикрепляет их к запросу;
- материалы опубликованной Knowledge Base.

### Сессионные данные

Desktop-клиент не сохраняет Supabase session через встроенный browser persistence.

Минимальная пара access/refresh token хранится через нативное системное credential storage ОС. Токены не записываются в localStorage или обычные настройки приложения.

### Audit и технические логи

Audit events используются для security-sensitive операций. Текущая реализация сознательно не записывает в audit metadata:

- полный текст пользовательского запроса;
- содержимое документов;
- Base64 изображений;
- access/refresh tokens.

Технические логи могут содержать диагностические идентификаторы запроса и технические коды ошибок.

## Для чего используются данные

Данные используются для:

- аутентификации;
- определения Tenant и доступных Server Profile;
- выполнения запросов к GovPro AI;
- работы с делами;
- поиска по опубликованной Knowledge Base;
- формирования ответов GovPro Model;
- проверки источников и provenance;
- защиты от злоупотреблений;
- аудита security-sensitive операций.

## Изоляция данных

Аутентификация сама по себе не даёт доступ к серверным данным. Видимость Server Profile определяется Tenant membership.

API проверяет tenant/profile scope, PostgreSQL использует RLS, а связанные таблицы дополнительно защищены composite foreign keys.

## Изображения и документы

Изображения проверяются на:

- MIME type;
- внутреннюю сигнатуру файла;
- размер одного файла;
- общий размер запроса;
- количество вложений.

Raw Base64 не сохраняется в истории чата desktop-клиента как долговременные данные.

Native PDF/Word/OCR pipeline пока не считается production-функцией и не должен рекламироваться как включённый до отдельного запуска и проверки privacy controls.

## Хранение и удаление

Конкретные сроки хранения зависят от production deployment и должны быть установлены владельцем продукта до Stable-релиза.

До публикации Stable нельзя утверждать, что существует единый глобальный срок хранения для всех инсталляций.

## Безопасность

Пользователь не должен отправлять в приложение:

- пароли;
- private signing keys;
- database credentials;
- model access tokens;
- чужие секретные данные без соответствующих оснований.

При обнаружении уязвимости не публикуйте эксплуатационные детали в открытом Issue. Используйте приватный канал безопасности проекта.
